tmux-agent-experience · tmag

让 tmux 知道你的 coding agents 正在做什么。

Claude Code、Codex、Pi 和 oh-my-pi 照常留在你的 tmux panes 中。看清谁需要你，一键跳过去，也让 agents 互相交接工作。

一段 prompt 完成安装 GitHub

从安装到第一次交接

需要 Linux 或 macOS 上的 tmux 3.2+、TPM 和 curl，大约十分钟。每一步都可以放心重复，之后更新 tmag 也是同样的步骤。

  1. 安装插件

    把这段话粘贴给你在 tmux 中运行的 coding agent。它会先征得你同意再修改 tmux 配置，随后接入它所在的 agent 宿主，并验证结果。

    Read https://raw.githubusercontent.com/ChrAlpha/tmux-agent-experience/main/SKILL.md and follow it to install or update tmag for the AI tool I am using.

    手动安装：在 TPM 的 run 行之上加入插件，然后按 prefix I。插件会下载与其版本匹配的已发布 tmag binary，校验 SHA-256，并保存在插件自己的目录中。

    set -g @plugin 'ChrAlpha/tmux-agent-experience'

  2. 接入 agents

    按 prefix M-a。弹窗列出通过各个 agent 自己的 plugin manager 安装 tmag 插件的命令，确认后执行，然后运行 tmag doctor。

  3. 开启新的 session

    Hooks 在 session 启动时加载，所以请在 tmux panes 中开启新的 agent session。在 Codex 中用 /hooks 批准 tmag 的 hooks，并运行一次 /title 开启 thread-id；Codex pane 在第一个 prompt 之后关联。

  4. 检查，然后交接

    tmag doctor 没有 ✗ 行即表示完成。按 prefix a 查看你的 agents，然后请其中一个邀请另一个参与：

    请 ~/src/web 里的 Codex agent review 我最近一次 commit，并等它回复。

    你的 agent 会运行 tmag send --wait，再运行 tmag read --last。Codex 从第一行看到是谁发来的，这一行由 tmag 写入：

    [tmag] From claude 1787a44e-…, another agent. Answer in your final message.

最佳实践

同时运行多个 agents 时，让 tmag 物尽其用的习惯。

留意需要你的时刻

01 把状态放在你本来就会看的地方

状态栏按状态统计 agents，pane 边框标出每一个，扫一眼就不必挨个切换 pane。保留你自己的 status-right，把 #{tmag_status} 加在其中任意位置。

在 TPM 的 run 行之上设置选项：插件在加载时读取它们。

# 状态栏显示 "1 blocked · 1 finished · 1 working"
set -g status-right '#{tmag_status} | %H:%M'
set -g status-right-length 60

# 每个 agent 的 pane 边框显示 "claude blocked permission"
set -g pane-border-status top
set -g pane-border-format ' #{pane_index} #{?#{E:@tmag-pane-status},#{E:@tmag-pane-status},#{pane_current_command}} '

set -g @plugin 'ChrAlpha/tmux-agent-experience'
run '~/.tmux/plugins/tpm/tpm'

02 让提醒来找你

Agent 在你没在看的 pane 中进入 blocked 或完成任务时，会响起所在 window 的 bell。prefix A 带你去等待最久的 agent，先处理 blocked，再处理你还没读过的已完成 turn；tmux 自带的 prefix M-n 和 M-p 在带标记的 windows 之间跳转。

离开终端时，@tmag-notify 会运行你自己的命令，提醒内容放在 TMAG_* 变量中；如果你最近一分钟在显示该 agent 的 server 上有过输入，则不运行。tmag notify 发送一条测试提醒。

# Linux 桌面
set -g @tmag-notify 'notify-send "$TMAG_TITLE" "$TMAG_MESSAGE"'

# macOS
set -g @tmag-notify 'osascript -e "on run argv" -e "display notification (item 2 of argv) with title (item 1 of argv)" -e "end run" "$TMAG_TITLE" "$TMAG_MESSAGE"'

与多个 agents 协作

03 一个 pane 一个 agent，一个任务一个 worktree

并行任务放在各自的 git worktree 中，就不会互相干扰。确实共享同一仓库的 agents，在切换分支、改写历史或停止进程之前，会先通过 tmag 查看彼此，并且不碰对方的改动。

git worktree add -b fix/login ../web-login
tmux new-window -n login -c "$(realpath ../web-login)"

04 用平常的话提出请求

委派工作时你不需要输入 tmag 命令。直接告诉你的 agent；tmag-peers skill 会选择合适的命令，tmag 通过对方 agent 自己的 channel 投递。正在工作的 agent 会在下一步读到消息；Claude Code 可能会先交给它的使用者批准。

第一行由 tmag 根据它所证实的发送者写入。你本人的 prompt 没有这一行，agent 也从不对自己的 session 执行操作。

你说tmag 执行
“请 Codex agent review 这份 diff，并等它回复。”send --wait，然后 read --last
“让另一个 agent 查查这个不稳定的测试，查到后把结果发给你。”send --reply；对方用 tmag reply 回复
“告诉 Pi agent，API schema 改了。”send

对方首先读到的内容，与上表逐行对应：

[tmag] From claude 1787a44e-…, another agent. Answer in your final message.
[tmag] From claude 1787a44e-…, another agent. When done, send your answer on stdin to: tmag reply 1787a44e-… -
[tmag] From claude 1787a44e-…, another agent. No answer needed.

05 审批权留在你手里

@tmag-answer 保持默认值 on 时，你可以在任意 pane 或脚本中决定 Claude Code 或 Codex 的 permission prompt，agent 自己的对话框同时保持打开。Agent 尝试这样做会被拒绝，因此 agents 之间不会意外地互相批准。

只有在你希望 agents 代为批准时才设为 agents；设为 off 则只在 agent 中决定。

$ tmag inspect 1787
…
request: 3fdce4c70dfa (permission, Bash)
…
$ tmag request 1787 3fdce4c70dfa
1787a44e permission asks: Bash
{
  "command": "go test ./..."
}
$ tmag answer 1787 3fdce4c70dfa allow
answered 1787a44e (hook) seq 1794457203091588

在此之上构建

06 脚本读 JSON，不读屏幕

把插件的 bin/ 加入 PATH。--json 遵循带版本的 tmag/v2 协议；tmag watch 先输出一份快照，之后每次变化输出一行，编号连续无缺口，订阅方因此知道自己错过了什么。

export PATH="$HOME/.tmux/plugins/tmux-agent-experience/bin:$PATH"

tmag list --json | jq -r '.sessions[] | select(.state == "blocked") | .id'
tmag wait 01a1 --for idle --timeout 30m && tmag read 01a1 --last
tmag watch

07 按你的规则，从别处访问 agents

要从别处访问 agents，请使用 remote companion，也就是 tmag-client。在一台机器（hub）上，tmag-client serve 在 tmux window 中运行，并跟随给定的各台机器；关闭该 window 即停止。每台设备用各自的一次性邀请配对，之后可以单独撤销任意一个。用你自己选择的隧道从别处访问：--tailscale 或 --access；推送需要其中一种。在 iOS 上，请先把页面添加到主屏幕，再从那里配对：主屏幕应用有自己的存储，在 Safari 中完成的配对不会带过去；通知也由主屏幕应用接收。

Client 来自它自己的 releases，安装方式见 wiki 的安装与更新页面。prefix M-r 仍会在 tmux window 中打开 tmag serve，用于 integrations 和任何命令都无法到达的机器。

# 在 hub 上：用 tmux window 跟随另一台机器
tmag-client serve --machine box='ssh box tmag' \
  --tailscale hub.example.ts.net --owner me@example.com

# 每台设备配对一次；之后可单独撤销
tmag-client auth pair phone
tmag-client auth list
tmag-client auth revoke ID

08 两个按键完成更新

prefix U 通过 TPM 更新插件，prefix M-a 把每个 agent 中的插件更新到相同版本。Codex 按插件版本批准 hooks：在新的 Codex session 中用 /hooks 再次批准 tmag 的 hooks。Pi 和 oh-my-pi 的 packages 随插件一起更新。

prefix + U      更新插件，它会获取匹配的 binary
prefix + M-a    更新每个 agent 中的 tmag 插件
/hooks          在新的 Codex session 中批准 tmag 的 hooks

tmag 不会碰的东西

  • 你的 agents。没有 daemon，也没有 wrapper：agents 按你的方式启动，tmag serve 只在你打开的 window 中运行。
  • 你的 turns。Hooks 采用 fail-open 机制，tmag 缺失或故障都不会阻塞任何一个 turn。
  • 你的内容。记录只保存 ids、状态、路径和时间。回复在被请求时从 agent 自己的 transcript 中读取，不做任何保存。
  • 猜测。只有进程表或 Codex 的 thread-id 标题证实时，pane 才会显示对应的 session；其余一律为 unknown。
  • 你的配置。Agent 插件通过各个 agent 自己的 plugin manager 安装；tmag 从不修改它们的设置。
  • 你的选择。每个默认行为都有关闭开关：@tmag-alert off、@tmag-seen off、设为 off 的按键选项，或者 @tmag-peers off 后按 prefix M-a，让 tmag 不进入 agents 的上下文。
